# T3 Bridge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a greenfield TypeScript MCP bridge (`t3-bridge`) that reliably drives T3 Code on menet2 via T3 Connect + DPoP, with tolerant v2 parsing and webhook wakes only when a prompt’s run completes.

**Architecture:** Stdio MCP server on the Grok Bot box. Auth/session + DPoP patterns inspired by `emmsixx/t3code-mcp` but new package with stable outbound JSON. Tolerant inbound v2 codecs. In-process watcher POSTs to a Grok Bot routine webhook once per watched `runId` on terminal status (attention states opt-in).

**Tech Stack:** Node.js ≥22, TypeScript, `@modelcontextprotocol/sdk`, `zod` (tolerant), Node built-in `fetch` / `WebSocket`, pnpm.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-10-25-t3-bridge-design.md` (authoritative).
- Default env menet2 `43972768-c214-40da-acbe-c9ea9a2e3bd4`; never hardcode secrets in repo.
- Outbound MCP results must be small, stable, versioned — never dump raw T3 projections.
- Webhook default: terminal run states only; `notifyOnAttention` opt-in.
- New threads default `runtimeMode: approval-required`.
- No web UI; no approving from the bridge; no worktrees.
- Reference checkout (patterns only, do not depend at runtime): if available on the build machine, otherwise use GitHub `emmsixx/t3code-mcp` branch with orchestration v2 prep — files `src/auth.ts`, `src/dpop.ts`, `src/http.ts`, `src/rpc.ts`, `src/protocol-v2.ts`, `src/store.ts`.
- Package name: `t3-bridge`. MCP server config name suggestion: `t3bridge`.
- TDD: failing test → implement → pass → commit per task.
